# WorkerPool для команды Kaspersky Container Security
### by Королёв Максим

---

### Описание структуры WorkerPool
Структура **WorkerPool** содержит канал **taskCh**, в котором хранятся задачи, приходящие из ручки  
Канал **doneCh** используется при закрытии пула. Когда все воркеры заканчивают работу, этот канал закрывается и закрытие программы идет дальше   
Флаг **isClosed** нужен для отслеживания, открыт ли пул для записи новых задач или нет  
Мапа **statuses** хранит в себе статусы всех задач, в том числе уже выполненных  
Мьютекс **mu** нужен для безопасного обновления флага **isClosed** и для обновления статусов в мапе  
Из конфига **cfg** берем количество воркеров и длину очереди

---

### Запуск WorkerPool
1. Для отслеживания выполнения всех воркеров используем waitGroup
2. В цикле запускаем воркеров, количество берем из конфига
3. После того, как все воркеры выполнили работу, закрываем канал doneCh

### Запуск воркера
1. Итерируемся в цикле по каналу taskCh. Цикл выполняется, пока канал открыт
2. Получаем задачу из канала
3. Запускаем цикл попыток выполнить задачу
4. Выполняем задачу. Если успешно, прекращаем попытки  
4.1 Если была ошибка, вычисляем backOff. Используем минимальное время backOff из конфига. Также проверяем, чтобы backOff был меньше максимального значения (добавил этот функционал, чтобы при большом количестве попыток backOff не стремился к бесконечности)  
4.2 Вычисляем джиттер 0 <= джиттер < backOff  
4.3 Ждем, затем возвращаемся в п.4
5. Ждем следующую таску

### Закрытие WorkerPool
1. Проверяем, не закрыт ли канал уже
2. Устанавливаем флаг **isClosed** в true
3. Закрываем канал тасок  
3.1 После выполнения текущей задачи, воркеры видят, что канал закрыт и заканчивают цикл  
4. Ждем завершения всех воркеров

### Добавление задачи в очередь
1. Локаем мьютекс
2. Проверяем, что очередь не закрыта
3. Пытаемся закинуть задачу в канал  
3.1 Если успешно закинули задачу, то отмечаем статус задачи как "в очереди"  
3.2 Иначе канал заполнен, возвращаем ошибку

### Получение статусов
1. Локаем мьютекс
2. Копируем мапу
3. Возвращаем мапу и анлокаем мьютекс

---

### Дополнение
1. Можно было прокинуть контекст в воркеры и проверять, не закрыт ли он перед каждой попыткой. В таком случае, мы бы ограничили количество попыток выполнения задачи после закрытия пула до 1
2. Можно было хранить статус задачи внутри структуры задачи, но в таком случае невозможно в рантайме узнать статус задачи. Поэтому я решил вынести статусы в отдельную мапу, чтобы появилась возможность узнать все статусы
3. Хост сервера хранится в переменной окружения SERVER_HOST
4. После выполнения задачи можно удалить ее из мапы статусов, но решил оставить для наглядности
